# 企业入驻与管理员权限设置入口

目标流程是：开发者把企业专属的官方权限设置 URL 发给企业管理员，管理员本人登录并在 UI 上选择、填写与维护规则。普通用户不填写 JSON。已有企业新增账号复用企业的类别、门店和维度，只补该账号的授权。

## 服务入口

权限 UI 已在当前服务实现，路径为官方网页域名下的 `/admin/:orgId/permissions`。开发者按目标环境验证企业专属固定 URL 后交付；页面可用不等于真实租户已配置或激活。一周会话与台账下载中心的源码实现不等于目标环境已部署；先核对目标服务版本和入口。agent 不凭本地代码或 Skill 更新推断目标页面可用，不生成临时管理凭据。

目标企业入口验证后，开发者可直接向管理员分享正式企业专属固定 URL；agent 也可向已知管理员提供已验证的入口。URL 是可收藏的入口，不是免登录赋权链接。新组织由本人在[官方注册页](https://app.smedatacenter.xyz/register)验证邮箱并创建首位管理员。页面未开放或给已有企业添加员工时交运维处理；密码设置仍由本人在第一方浏览器完成。

管理员 UI 与登录／密码页面均支持中文和 English，首次默认中文。沿用用户明确选择的合法语言偏好，缺失或异常时中文兜底；语言切换不改变权限或业务名称。密码、会话与设置链接不得交给 agent 或写入文件。

## 用户操作约定

1. 用户要求代注册时只引导本人打开官方注册页。本人输入验证码、密码并创建企业，注册邮箱成为首位管理员。运维也可受控建立新组织和首管。新组织开户时登记固定类别并启用权限规则。运维私下交付一次性密码设置链接，页面企业专属固定 URL 与密码设置链接分开说明。账号、角色和密码管理不转交本 Skill。
2. 管理员打开企业专属固定入口；同一浏览器／用户配置的官方设备网页登录状态在 七天（604800 秒）绝对有效期内可复用，访问不续期；旧会话保留原失效时间，重新登录才使用新期限。失效或换浏览器需登录。服务端核对 URL 企业、账号企业与当前 admin，A 企业链接误发给 B 时拒绝访问，不泄露 A 信息、不自动改跳 B。核对当前企业和账号。新企业按首次设置引导，已有企业直接查看当前配置；不能通过 URL 参数或填写另一个组织 ID 切租户。
3. 在 UI 设置已登记固定类别的业务密级、精确门店与适用条件，为每个账号（包括管理员本人）选择读取类别与范围。全部门店必须说明“包含以后新增门店”，集团资料单独授权。原始配送台账继续内部使用，不展示密级配置，不要求为启用或入库设置密级，也不提供普通读取开关。配送台账 PDF 保留独立密级与授权。
4. 普通文档按整份声明类别、文件密级和完整范围；结构化原件沿用成功解析的完整数据要求，不另填原件权限。缺项不能猜测或默认成全部访问。
5. 保存前核对具体变更，尤其是撤权。页面提示读取已暂停时，由运维协同当前管理员处理。
6. 管理员完成后，员工可通过 get_my_permissions 查看本人实时权限卡；登录或卡片本身不能证明某份业务资料已可读，实际请求由服务端判定。

## 企业名称与首店保存

在匹配服务版本的“门店与业务企业 → 新增精确门店”中，管理员可选择“新增企业…”，填写企业名称和门店名称后一次保存。后台自动、原子地建立企业信息和首店，不需要额外登记或上传一条评价来初始化。也可用“新增业务企业”单独保存名称；已有企业直接选择，不重复建立。页面与评价工具共用正式企业目录，不从组织名、门店 key 或历史资料推断名称，不做历史补齐。

类别密级和账号读取授权由管理员显式设置。名称冲突或缺少名称时，保留原权限，按页面提示核对；不得自动改名、合并或绕过错误。没有真实评价时，权限配置就绪与查询空结果不等于实际写入验收。

## MCP 管理边界

用户明确选择 MCP 管理且已获授权时，可用[已发布的管理员 MCP 工具](business-authorization.md#admin-tools)，不要求用户填写 JSON，也不绕过服务端管理授权。先读取现有配置和最新版本、展示具体变化；账号更新是整套 grant 替换，保留未批准删除的条目。跨请求重读版本，冲突先核对，不盲目重试。

固定类别随开户或服务发布迁移登记，初始密级显示「未配置」。现有资料缺少权限属性时，按服务返回的缺项核对。真实回填、账号创建、SQL／SSH／云端操作不属于本 Skill。普通员工不能列出其他账号配置，也不能仅凭企业专属固定 URL 取得管理权限。

用户明确选择 MCP 管理时仍可使用现有工具，不强制跳转 UI。仅在明确需要内部记录时读取[内部 JSON 约定](tenant-onboarding-json.md)；内部记录不作为用户交付要求，也不授权后台导入或真实租户切换。

固定类别密级配置要求服务端已部署原始台账内部类别免密级修正；内部资料类别缺失时请联系运维核对服务初始化。

## 固定类别

匹配服务版本发布后，在「类别与密级 → 固定类别」打开或刷新即可看到「门店巡检问卷」或
`cost_cards` 等新增类别。管理员按需保存密级并显式授权。仍缺类别时，请运维核对服务发布。
成本卡的集团授权与配方适用门店独立，详见[成本卡](cost-cards.md)。
